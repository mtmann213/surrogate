Chronological engineering log for the configurable datalink workbench.

This file is meant to answer: what did we change, why did we do it, what did we

## 2026-05-29 - Orientation And Master Plan

### Context

The repo started as a GNU Radio/USRP datalink surrogate with an existing PyQt
GUI, TX/RX flowgraphs, FEC, spreading codes, baseband FHSS, anomaly injection,
IQ recording, and hardware diagnostics.

Several sibling/related projects were inspected:

- `../surrogate-qwen`
- `../surrogate2`
- `../surrogate4`
- `~/opal-vanguard`

### Findings

- Current repo is the best primary hardware/runtime base.
- `surrogate-qwen` is the closest fork and contains useful test/jammer ideas.
- `surrogate2` and `surrogate4` have cleaner package/test patterns.
- `opal-vanguard` has mature link-layer ideas: packetizer/depacketizer,
  whitening, interleaving, NRZI, CCSK/Barker, Reed-Solomon variants, regression
  suite patterns, and adversary/jammer concepts.

### Decision

Use this repo as the primary cleaned-up repo. Cherry-pick ideas from sibling
projects only when they fit the new architecture.

### Output

Added `MASTER_PLAN.md`, a detailed architecture and milestone document.

## 2026-05-29 - Milestone 1: Profile Foundation

### Goal

Create a pure Python datalink profile engine before touching GNU Radio.

### Changes

Added `core/datalink_profile.py`.

Capabilities:

- exact preamble bits
- exact syncword bits
- syncword bit-error tolerance
- inverted-frame handling
- uint header fields
- raw payload length field semantics
- auto-increment counter
- header CRC
- payload CRC
- padding
- optional convolutional K=7 rate 1/2 FEC
- optional matrix interleaving
- optional LFSR whitening
- derived payload-region and frame lengths
- YAML profile loading

Added first profile:

- `config/profiles/bpsk_static_v1.yaml`

Added tests:

- `tests/test_datalink_profile.py`
- `tests/test_fec_codec.py`
- `tests/__init__.py`

### Important Bug Found

The existing convolutional decoder traced back from final state 0. With this
encoder's shift-register convention, appending `K-1` zero tail bits does not
force every input length to numeric final state 0. This caused roundtrip errors
for several byte lengths.

Fix:

- Trace back from `np.argmin(path_metrics)`.

Regression:

- `tests/test_fec_codec.py` now checks byte lengths 1 through 31.

### Verification

## 2026-06-01 - BPSK Runtime Hardware Checkpoint

### Goal

Prepare a conservative, honest live-radio checkpoint for the first cabled B210
loopback test.

### Hardware Setup

- B210 serial: `34D6458`
- TX path: RF0 `TX/RX`
- RX path: RF1 `RX2`
- Inline attenuation: 60 dB
- Initial gains: TX 35 dB, RX 35 dB
- Center frequency: 915 MHz
- Sample rate: 1 MS/s
- Modulation: BPSK
- Hopping: disabled for the first run

### Changes

- Updated `config/default_config.yaml` for the current B210 serial, 1 MS/s
  sample rate, 1 MHz RF bandwidth, and conservative 35/35 dB gains.
- Limited live GNU Radio runtime modulation to BPSK and added a guard so QPSK,
  8PSK, and DPSK fail loudly instead of silently using the wrong path.
- Kept the pure modulation/demodulation helpers for future modem work.
- Changed `FrameSink` to accept complex chips and estimate per-frame phase from
  the preamble correlation peak before despreading.
- Reset link stats on restart and exposed detection/decode rates in the status
  panel.
- Rebuilt the hop sequence when constructing flowgraphs and kept baseband
  hopping on the GNU Radio sample counter path.

### Important Runtime Decision

The attempted 8PSK flowgraph wiring was not committed as a live runtime mode.
It packed the entire chip stream into 3-bit symbols, which conflicts with the
current chip-oriented preamble and frame sink assumptions unless frame lengths
and preamble alignment are designed around symbol packing. QPSK also did not
have a real runtime path. The runtime is therefore intentionally BPSK-only for
this hardware checkpoint.
